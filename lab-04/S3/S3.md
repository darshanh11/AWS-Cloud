## 1. What is Amazon S3?

### Explanation

**Amazon Simple Storage Service (Amazon S3)** is an AWS cloud storage service used to store and retrieve data.

Amazon S3 is an **object storage service**. It allows users and applications to store different types of files in the AWS Cloud.

Amazon S3 can store:

- Images
- Videos
- Documents
- PDF files
- Backup files
- Log files
- Application files
- Static website files

The data stored in Amazon S3 is called an **Object**.

Objects are stored inside containers called **Buckets**.

### S3 Structure

```text
AWS Cloud
    |
    v
Amazon S3
    |
    v
S3 Bucket
    |
    v
Objects
    |
    +---- Images
    +---- Documents
    +---- Videos
    +---- Backups
```

### Practical Steps

1. Sign in to the **AWS Management Console**.
2. Search for **S3**.
3. Open the **Amazon S3** service.
4. Explore the S3 dashboard.
5. Review the options for Buckets, Objects, Access Points, and other S3 resources.

### Result

**Successfully opened the Amazon S3 service and understood that S3 is an AWS object storage service used to securely store and retrieve data.**

## 2. Amazon S3 Components

### Explanation

The major components of Amazon S3 are:

- Buckets
- Objects
- Keys
- Prefixes
- Regions

### S3 Bucket

An **S3 Bucket** is a container used to store objects.

Before uploading any file to Amazon S3, a bucket must be created.

Example:

```text
Bucket Name:
darshan-aws-s3-lab
```

### S3 Object

An **Object** is the actual data or file stored inside an S3 bucket.

Examples:

```text
resume.pdf
image.jpg
backup.zip
report.txt
```

### S3 Key

A **Key** is the unique identifier or name used to identify an object inside an S3 bucket.

Example:

```text
documents/resume.pdf
```

### Prefix

A **Prefix** is used to organize objects and is similar to a folder path.

Example:

```text
darshan-aws-s3-lab
|
+---- documents/
|      |
|      +---- resume.pdf
|
+---- images/
|      |
|      +---- cloud.jpg
|
+---- backups/
       |
       +---- backup.zip
```

### Region

An S3 bucket is created in a selected AWS Region.

Example:

```text
Asia Pacific (Mumbai)
ap-south-1
```

## 7. S3 Versioning

### Explanation

**Amazon S3 Versioning** allows multiple versions of the same object to be stored inside a bucket.

Versioning helps protect data against:

- Accidental deletion
- Accidental overwrite
- Unwanted modifications

Example:

```text
resume.pdf
|

|

|
```

When a file is modified and uploaded again, S3 can maintain the previous versions when Versioning is enabled.

## 8. Amazon S3 Storage Classes

### Explanation

Amazon S3 provides different storage classes based on data access frequency, availability, performance, and cost requirements.

### S3 Standard

Used for frequently accessed data.

Examples:

- Active application files
- Website files
- Frequently used documents

### S3 Intelligent-Tiering

Used to automatically move data between access tiers based on usage patterns.

### S3 Standard-IA

Used for infrequently accessed data that still requires rapid access.

Examples:

- Backup files
- Disaster recovery data

### S3 One Zone-IA

Stores data in a single Availability Zone.

It can be used for data that can be recreated if required.

### S3 Glacier Instant Retrieval

Used for archive data that requires fast access.

### S3 Glacier Flexible Retrieval

Used for archive data where retrieval can take longer.

### S3 Glacier Deep Archive

Used for long-term data storage and archiving.

Examples:

- Historical records
- Long-term backups
- Old documents

### Storage Class Structure

```text
Frequently Accessed
        |
        v
S3 Standard
        |
        v
Less Frequently Accessed
        |
        v
S3 Standard-IA
        |
        v
Archive
        |
        v
S3 Glacier
        |
        v
Long-Term Archive
        |
        v
S3 Glacier Deep Archive
```

### Result

**Successfully understood the major Amazon S3 Storage Classes and their different use cases.**

## 10. S3 Encryption

### Explanation

Encryption protects data stored in Amazon S3.

Amazon S3 supports different server-side encryption methods.

### SSE-S3

```text
Server-Side Encryption with Amazon S3 Managed Keys
```

AWS manages the encryption keys.

### SSE-KMS

```text
Server-Side Encryption with AWS Key Management Service
```

AWS Key Management Service is used to manage encryption keys.

### SSE-C

```text
Server-Side Encryption with Customer-Provided Keys
```

The customer provides and manages the encryption keys.

### Encryption Flow

```text
User Uploads Object
        |
        v
Amazon S3
        |
        v
Encryption Applied
        |
        v
Encrypted Object Stored
```

### Practical Steps

3. Find the encryption settings.
4. Review the available server-side encryption options.
5. Select the required encryption configuration.
6. Save the configuration.
7. Upload an object.
8. Verify that the required encryption settings are applied.

**Successfully understood how encryption protects objects stored in Amazon S3.**

## 12. IAM Permissions for Amazon S3

### Explanation

IAM permissions control what actions an IAM User, Group, or Role can perform on Amazon S3 resources.

Common S3 permissions include:

```text
s3:ListBucket
s3:GetObject
s3:PutObject
s3:DeleteObject
```

### IAM Permission Flow

```text
IAM User
    |
    v
IAM Policy
    |
    v
S3 Permission
    |
    v
Allow or Deny
    |
    v
S3 Bucket
```

### Example IAM Policy

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "s3:ListBucket"
      ],
      "Resource": "arn:aws:s3:::darshan-aws-s3-lab"
    },
    {
      "Effect": "Allow",
      "Action": [
        "s3:GetObject",
        "s3:PutObject"
      ],
      "Resource": "arn:aws:s3:::darshan-aws-s3-lab/*"
    }
  ]
}
```

### Result

**Successfully understood how IAM Policies control permissions for Amazon S3 buckets and objects.**

## 15. Authentication and Authorization

### Authentication

Authentication verifies:

```text
Who are you?
```

Example:

```text
An IAM User signs in using valid AWS credentials.
```

### Authorization

Authorization determines:

```text
What are you allowed to do?
```

Example:

```text
Can the user upload an object?
Can the user download an object?
Can the user delete an object?
```

### Authentication and Authorization Flow

```text
User Request
     |
     v
Authentication
     |
     v
IAM Identity Verified
     |
     v
Authorization
     |
     v
IAM and S3 Policies Evaluated
     |
     v
Allow or Deny
```

### Result

**Successfully understood the difference between Authentication and Authorization in Amazon S3 access.**

## 16. Principle of Least Privilege

### Explanation

The **Principle of Least Privilege** means giving only the minimum permissions required to complete a task.

Example:

If a user only needs to upload objects, the user can receive:

```text
s3:PutObject
```

The user should not automatically receive:

```text
s3:DeleteObject
```

unless deletion permission is required.

### Example

```text
User Requirement:
Upload files

Required Permission:
s3:PutObject

Unnecessary Permission:
s3:DeleteObject
```

### Result

**Successfully understood the Principle of Least Privilege and its importance in securing Amazon S3 access.**
